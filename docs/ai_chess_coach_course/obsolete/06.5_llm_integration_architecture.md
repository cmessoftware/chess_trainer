## 1. Design principles

| Principle | Implementation |
|-----------|----------------|
| Provider-agnostic LLM | `llm/base.py` → `LLMProvider.generate(prompt)` |
| Diagnosis in Python, narration in LLM | `DiagnosisBuilder`, RCA, validation before/after LLM |
| No raw ML/engine in prompts | `critical_move_contract`, `prepare_single_game_brief_for_llm()` |
| CI never calls paid APIs | `DryRunProvider` when API key missing; pytest mocks |
| Quota-safe notebooks | Optional LLM cell; deterministic fallback on validation failure |

## 2. End-to-end pipeline (Phase A — single game)

```text
course_training_dataset.parquet + course_data.sqlite
        ↓
split_by_game_id → val_df
        ↓
prepare_player_game_analysis() → game_id(s)
        ↓
explain_player_games()  →  SHAP + Pattern Engine v1 per move
        ↓
analyze_critical_moves() / build_verbal_game_brief()
        ├─ game_timeline (features + tags from SQLite when available)
        ├─ root_cause.py (walkback + incident clustering)
        ├─ DiagnosisEngine (board detectors, python-chess)
        └─ DiagnosisBuilder (tags → tactical; else board; V6 styles)
        ↓
prepare_single_game_brief_for_llm()
        ├─ normalize_critical_move_for_llm()  (V3 contract)
        └─ synthesize_lessons()  (V7 lesson_clusters + phase_summary)
        ↓
build_single_game_coaching_prompt()  (V7 four-section rules)
        ↓
generate_single_game_coaching()  (coaching_generate.py)
        ├─ validate_critical_moves()
        ├─ optional LLMProvider.generate()
        ├─ validate_coaching_response()  (V7 sections + move guardrails)
        └─ render_deterministic_coaching() fallback
        ↓
artifacts/module06_5/ + debug/phase_a/
```

**Phase B (profile sample):** same pattern engine + `build_coaching_context()` + profile prompt; still v1-style output (not V7 four-section yet).

## 4. LLM providers (implemented)

### 4.1 Interface

```python
class LLMProvider(ABC):
    @abstractmethod
    def generate(self, prompt: str) -> str: ...
```

### 4.2 Configuration (`.env`)

See [`.env.example`](./.env.example).

| Variable | Purpose |
|----------|---------|
| `LLM_PROVIDER` | `deepseek` (default), `gemini`, `openai_compatible` |
| `LLM_MODEL` | e.g. `deepseek-chat`, `gemini-2.5-flash` |
| `DEEPSEEK_API_KEY` | DeepSeek Bearer token (`sk-...`) |
| `GEMINI_API_KEY` | Gemini (legacy name still supported) |
| `LLM_API_KEY` | Generic override |
| `LLM_BASE_URL` | Default `https://api.deepseek.com` for DeepSeek |
| `LLM_TEMPERATURE` | Default `0.4` |
| `LLM_FALLBACK_ON_QUOTA` | `true` → placeholder text instead of raise |

Keys are loaded from repo root `.env` or `docs/ai_chess_coach_course/.env` via `load_course_env()`.

### 4.3 Provider matrix

| Provider | Module | SDK / transport | Notes |
|----------|--------|-----------------|-------|
| **DeepSeek** | `openai_compatible_provider.py` | `POST /v1/chat/completions` | Recommended for cost; no extra pip package |
| **Gemini** | `gemini_provider.py` | `google-genai` | Free tier ~20 req/day on Flash |
| **Dry run** | `dry_run_provider.py` | — | Used when API key empty (CI, local dev) |

Factory: `create_provider(load_llm_settings())` in `provider_factory.py`.

**Future (not implemented in course package):** Ollama / local HTTP — same `OpenAICompatibleProvider` pattern with `LLM_BASE_URL=http://localhost:11434/v1` when Ollama exposes OpenAI API.

### 4.4 Invocation policy

| Context | Live LLM? |
|---------|-----------|
| `pytest` / CI | **Never** (dry-run or injected mock provider) |
| Notebook Phase A/B build cells | **No** — writes prompts only |
| Notebook optional cell `INVOKE_GEMINI=True` | **Yes** — uses `LLM_PROVIDER` from env (name is legacy) |

## 5. Diagnosis stack (V4–V6, Python-only)

Responsibility: **what** each mistake was — before the LLM writes prose.

```text
Critical move row (parquet + SQLite tags/features)
        ↓
DiagnosisBuilder.build()
        ├─ interpret_tactical_tags()     if SQLite tags actionable
        ├─ DiagnosisEngine.diagnose()    else python-chess detectors
        ├─ interpret_features() + interpret_shap()  → supporting_features (not sent as raw SHAP)
        ├─ classify_diagnosis_type()     tactical | opening | positional | endgame | …
        └─ apply_diagnosis_style()       V6 templates; opponent_reply only if tactical
        ↓
StructuredDiagnosis → critical_moves[] moment dict
        ↓
normalize_critical_move_for_llm()
```

**Known data quality caveat:** precomputed SQLite tags (e.g. `discovered_attack`) can be noisy; the LLM faithfully paraphrases payload `issue`/`theme`. Fixing upstream tagging improves coaching more than prompt tweaks.

## 6. V7 insight-based coaching (implemented)

Spec: [accc_llm_coaching_recommendations_v7.md](./accc_llm_coaching_recommendations_v7.md).

| V7 requirement | Code |
|----------------|------|
| Four sections in player-facing report | `prompt_builder.SINGLE_GAME_COACHING_RULES`, `deterministic_coaching.py` |
| 2–3 lessons merging related moves | `lesson_synthesizer.synthesize_lessons()` → `lesson_clusters` in LLM JSON |
| Critical moves as concise evidence | `### Momentos clave` + validation entry count |
| Training plan linked to lessons | Prompt + deterministic renderer |
| No SHAP/features in text | CONTROL RULES + `prompt_contains_forbidden_jargon()` tests |
| Post-LLM guardrails | `coaching_validation.validate_coaching_response()` |

LLM payload shape (Phase A):

```json
{
  "player": "…",
  "game": { "opponent", "result_description", "opening", "overall_impression" },
  "phase_summary": { "opening": "…", "middlegame": "…", "endgame": "…" },
  "lesson_clusters": [
    {
      "title": "…",
      "idea": "…",
      "evidence_moves": ["6. Nc3"],
      "why": "…",
      "how_to_avoid": "…"
    }
  ],
  "critical_moves": [ { "move_number", "player_move", "issue", "lesson_hint", "diagnosis_type", "context_pgn", … } ]
}
```

Orchestration entry point:

```python
generate_single_game_coaching(brief, debug_dir=..., invoke_llm=False)
```

## 8. What the LLM must never receive

- Raw SHAP vectors, feature column names, `score_cp`, numeric `score_diff` in player text
- Full game PGN (only `context_pgn` windows per moment)
- Deprecated fields: bare `move`, `tactical_line` as primary contract (normalized to `player_move` / `opponent_reply`)

Profile Phase B context: aggregated patterns and game list — same forbidden-field rules via `validate_coaching_context()`.
